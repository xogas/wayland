## 目标 (做什么)

1. 使用者可以在 linux/amd64 上 clone 仓库后直接 `go build`, 得到不依赖 libwayland.so 的单文件客户端程序.
2. 系统在运行开发期生成入口时, 可以读取 68 个 XML, 生成并更新根包与 `protocols/` 下的 Go 绑定; 连续两次生成无 diff.
3. 使用者在 sway 上可以通过 Unix socket 完成连接, 线协议编解码与对象/事件分发; 调用方可以从不止一个 goroutine 发请求.
4. 系统在运行验证链时, 可以在不引用 C 实现的前提下, 对 68 个 XML 完成 DTD 校验, 解析与生成元数据一致, 语义不变量与全签名编解码测试.
5. 使用者在 v0.1.0 可以在 sway 上跑通 5 个示例, 并用 registry-bind 覆盖 sway 广告的全部 global, 退出码 0.

## 非目标 (这次坚决不做)

- 不做 Wayland 服务端: 不实现 compositor, 不接受客户端连接, 不生成服务端绑定.
- 不引入 CGO, 不链接 libwayland: 库与示例的构建不出现 cgo, 运行时不依赖 libwayland.so; 不调用 wayland-scanner 或其他 C 实现.
- 不支持 X11/XWayland: 不读取 `DISPLAY`, 不调用 Xlib 或 xcb.
- 不做 GPU 与显示后端: 不实现 EGL, OpenGL, Vulkan, DRM, GBM, 不提供渲染 API; 68 个协议的绑定照常生成, 但 5 个示例只用 `wl_shm` 缓冲.
- 不做高层 UI: 不提供窗口管理, 控件, 布局, 主题; 5 个示例直接调用协议, 只创建各自需要的最小窗口.
- 不提供运行时协议加载: 不在程序启动时解析 XML, 不做插件式协议; 绑定在开发期生成并提交.
- 不声称未被 sway 广告的协议在运行时可用: 交付说明按协议标注 "真实连接已验证" 或 "仅绑定与编解码已验证".

## 范围冻结

### In Scope

- 开发期生成 (对应意图: 成功的样子 - 生成入口, 数据一致): 一条入口读取 68 个 XML; 根包放 wayland.xml 绑定, `protocols/` 放其余; 生成代码提交; 两次生成无 diff.
- 客户端运行时 (对应意图: 成功的样子 - 库范围, 线协议): Unix socket 连接; 线协议编解码 (主机字节序, 小端); 对象 ID 管理; 事件分发; 调用方可以从不止一个 goroutine 发请求, 回调串行.
- 协议绑定 (对应意图: 成功的样子 - 库范围, 数据一致): 68 个协议的 Go 绑定, 含 experimental; experimental 跟随上游.
- v0.1.0 示例 (对应意图: 成功的样子 - 真实会话): registry, shm-surface, xdg-shell, input, output 5 个独立程序.
- 验证链 (对应意图: 成功的样子 - 数据一致, 语义不变量, 线协议, registry-bind, 边界): DTD 校验 68 个 XML; 解析与生成元数据一致; 语义不变量; 全签名编解码; registry-bind; sway 实跑; 无 C 对照.

### Out of Scope

- 服务端/compositor 与服务端绑定.
- CGO, libwayland, wayland-scanner, C 实现对照.
- X11/XWayland.
- EGL/OpenGL/Vulkan/DRM/GBM 与渲染 API.
- 高层 UI/窗口管理/控件/布局/主题.
- 运行时 XML 解析/插件式协议.
- 其他 OS/架构, 大端, 构建标签.
- 第三方 Go 依赖.
- 68 XML 与 5 示例之外的新协议或新示例.
- 上游协议自动同步/版本检测; 升级由人工替换 XML 后重新生成.
- 性能/吞吐 SLA; 只在 L4 记录基线, 不作为 v0.1.0 门禁.

### 边界项

- experimental: 生成 In; 真实连接验证 Out.
- sway 未广告协议: 生成与编解码 In; 真实连接验证 Out.
- 废弃的 `wl_shell`: 生成 In; 示例 Out.
- 生成入口的具体命令与 flag 拼写: 细节, 由 L2 定; L1 只锁存在一条开发期生成入口.
- API 形状, 事件分发细节, 包内类型布局: 细节, 由 L3 定; L1 只锁能力.
- 同名协议的不同版本: 按源目录各自生成 (如 stable 与 unstable 的 xdg-shell), 不做跨版本合并; 示例使用 stable.

## 放弃条件 (什么情况下立即停止)

- 如果生成器在两次修复后, 同一输入连续两次生成的 `git diff --exit-code` 仍非 0, 则停止生成器开发并重评方案 (事实来源: 两次生成的命令输出).
- 如果 registry 示例在两次实现后在 sway 上仍无法列出 global, 或出现 protocol error, 则停止运行时开发并重评传输与编解码 (事实来源: 示例 stdout/stderr 与退出码).
- 如果 wayland.xml 与 stable/xdg-shell 的解析或生成结果在两次人工核对后仍有差异, 则停止后续阶段, 先修解析器与生成器 (事实来源: 核对记录).
- 如果实现需要 CGO, libwayland, wayland-scanner, C 对照, 第三方依赖, X11, GPU 或其他平台才能继续, 则停止并回 L1/L0 重评 (事实来源: `go.mod`, 构建配置, 代码 diff).
- 如果连续 2 个实现切片未通过 G4 (AC 证据缺失或不可复现), 且没有可行修复, 则降级范围或停止 (事实来源: `docs/evidence/coverage.md` 与证据文件).
- 如果并发契约在两次设计迭代后仍无法通过 `go test -race`, 或出现 deadlock, 则停止并重评事件分发设计 (事实来源: 测试输出与 stack trace).

> 时间维度不适用: `docs/intent.md` 明确个人项目无截止日期; 用连续失败次数与硬指标替代.
