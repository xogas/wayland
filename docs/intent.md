# 意图包: wayland (Go 客户端库)

- **版本**: v1.0 / **状态**: Frozen
- **一句话目标**: 独立开发者 (库作者本人) 想要一个纯 Go 的 Wayland 客户端库, 附带一个扫描仓库内协议 XML 并生成 Go 绑定的 cmd, 因为现有 Go 绑定依赖 CGO 与 libwayland, 每做一个 Linux 桌面小工具都要重新处理静态链接与交叉编译.
- **使用者**: 独立开发者 (库作者本人), 在 Linux 桌面的 sway 会话里写截图, 启动器一类小工具; 每做一个新工具复用一次, 预计每月 1 次; 每次都需要从干净 clone 直接构建出单个静态二进制, 并在本机 sway 上运行.
- **当前痛点**: 现有 Go Wayland 绑定依赖 CGO 与 libwayland; 每个新工具都要重新处理静态链接与交叉编译, 约每月 1 次, 每次约半天; 产物还依赖目标机上的 libwayland.so, 无法单文件分发.
- **成功的样子**:
  - 库范围: 覆盖从 Unix socket 连接, 线协议编解码, 对象与事件分发, 到 68 个协议的 Go 绑定; 调用方不需要自己实现 socket 读写与消息分发.
  - 生成入口: 在干净 clone 上执行仓库根的一条生成命令 (入口形式在规格阶段固定), 输入为 `wayland-protocols/` 下 68 个 XML, 输出为仓库内更新后的 Go 绑定; 连续执行两次, `git diff --exit-code` 为 0; 随后 `go build ./...` 与 `go vet ./...` 通过.
  - 数据一致: 68 个 XML 全部通过 `wayland.dtd` 校验; 对每个 XML, 解析结果与 XML 源逐项一致 (interface 名称与版本, request/event 名称与 opcode, 参数类型, 接口引用与 enum 引用, enum 名称与取值); 生成代码中的元数据与解析结果逐项一致; 差异数为 0.
  - 语义不变量: 所有 interface 引用与 enum 引用可解析; 每个 request/event 的 opcode 从 0 连续; 每个 `since` 不超过所属 interface 版本; enum 取值不重复且能由 32 位整数表示.
  - 线协议: 覆盖全部 request/event 签名的编解码用例 (每条至少 1 例), 参数类型包含 int, uint, fixed, string, array, fd, new_id, object, 空 string/array, 对齐补零; 截断消息必须返回错误且不 panic; `go test -race ./...` 通过.
  - 真实会话: v0.1.0 交付时, 5 个示例各自可独立运行; 在 sway 会话 (`WAYLAND_DISPLAY=wayland-1`) 上, 每个示例退出码 0:
    - registry: 输出 sway 广告的 global, 数量大于 0, 且包含 `wl_compositor`, `wl_shm`, `xdg_wm_base`.
    - shm-surface: 创建 200x200 的 xdg 窗口, 用 `wl_shm` 显示纯色, 1 秒后退出.
    - xdg-shell: 创建 400x300 窗口, 标题为 `wayland-go demo`, 按 Esc 或关闭按钮后退出.
    - input: 在窗口中打印键盘 keycode 与指针坐标, 按 Esc 退出.
    - output: 输出每个显示器的 name, 当前模式分辨率, scale; 显示器数量大于 0.
  - registry-bind: 对 sway 广告的每个 global 按广告版本绑定; 全程无 protocol error; 断开连接后进程退出码 0.
  - 边界: sway 未广告的协议, 只声称 "XML/DTD 校验, 生成结果与 XML 源一致, 语义不变量通过, 编解码用例通过", 不声称真实连接可用; 这条写进交付说明.
- **明确的非目标**:
  - 不做 Wayland 服务端: 不实现 compositor, 不接受客户端连接, 不生成服务端绑定.
  - 不引入 CGO, 不链接 libwayland: 库与示例的构建不出现 cgo, 运行时不依赖 libwayland.so; 不调用 wayland-scanner 或其他 C 实现.
  - 不支持 X11/XWayland: 不读取 `DISPLAY`, 不调用 Xlib 或 xcb.
  - 不做 GPU 与显示后端: 不实现 EGL, OpenGL, Vulkan, DRM, GBM, 不提供渲染 API; 68 个协议的绑定照常生成, 但 5 个示例只用 `wl_shm` 缓冲.
  - 不做高层 UI: 不提供窗口管理, 控件, 布局, 主题; 5 个示例直接调用协议, 只创建各自需要的最小窗口.
  - 不提供运行时协议加载: 不在程序启动时解析 XML, 不做插件式协议; 绑定在开发期生成并提交.
  - 不声称未被 sway 广告的协议在运行时可用: 交付说明按协议标注 "真实连接已验证" 或 "仅绑定与编解码已验证".
- **已知约束**:
  - 语言与依赖: Go 以 `go.mod` 的 `go 1.27.4` 为下限; 只用标准库; 第三方 Go 依赖为 0.
  - 构建: 纯 Go, 无 CGO; 在 linux/amd64 上构建单个静态二进制; 其他平台默认不支持, 不添加构建标签.
  - 平台与字节序: 仅 linux/amd64; Wayland 线协议按主机字节序, 该平台为小端, 不做字节序转换.
  - 生成代码布局: wayland.xml 的绑定在模块根包; 其余协议在 `protocols/` 下按 stable/staging/unstable/experimental 与协议目录生成.
  - 协议源: `wayland-protocols/` 下的 wayland 1.26.0 与 wayland-protocols 1.50, 共 68 个 XML; 生成器递归扫描该目录.
  - 生成方式: 开发期生成, 生成代码提交进仓库; 使用者 clone 后直接 `go build`, 不需要先跑生成器.
  - 实现依据: 协议 XML, wayland.dtd 与公开协议文档; 不以 C 代码为依据, 不使用 wayland-scanner; 线协议以协议文档为准, 以真实合成器互通为验收.
  - 并发: 调用方可以从不止一个 goroutine 同时发起请求; 事件分发与核心状态由库内部串行处理, 回调不会并发执行; 调用方不需要额外加锁.
  - experimental: 跟随上游版本; 每次上游更新协议 XML 后重新生成; 不承诺 API 跨版本不变.
  - 个人项目: 无截止日期; 完成标准以 "成功的样子" 为准.
  - 验收机: 当前 sway 会话的 `WAYLAND_DISPLAY=wayland-1`.
