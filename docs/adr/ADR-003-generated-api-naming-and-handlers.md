# ADR-003: 生成代码的命名与事件处理形态

- **状态**: Accepted
- **日期**: 2026-11-15
- **决策人**: 库作者
- **触发**: 改变对外契约 (生成 API)
- **不可逆性**: 高

## 背景

`docs/spec.md` 只锁行为, 把导出标识符, 方法形态与 handler 形态留给 L3. 生成代码覆盖 68 个协议, 命名必须无歧义且可机械生成; 事件回调必须串行; 用户要能只实现自己关心的事件.

## 备选方案

| 方案 | 优点 | 缺点 |
| :--- | :--- | :--- |
| A. 保留完整前缀 (`WlDisplay`, `XdgWmBase`) | 可预测, 无剥前缀规则 | 冗长; 包名已表达协议 |
| B. 按包剥离协议前缀 (`Display`, `WmBase`) | 可读; 包名承担上下文 | 需要碰撞检测与回退规则 |
| C. 每协议自定义映射 | 最灵活 | 维护成本高; 生成器复杂 |

事件形态:

| 方案 | 优点 | 缺点 |
| :--- | :--- | :--- |
| A. 每接口 handler 接口 | 类型安全; 只实现关心的方法 | 接口方法多时样板多 |
| B. handler struct 的 func 字段 | 按需赋值 | 可变; 契约更松 |
| C. event channel | 调用方自选模型 | 与 spec 的串行回调契约冲突 |

## 决策

选择命名 B 与 handler A.

- 每个协议包计算 interface 名的公共前缀 (按 `_` 边界); 剥离它得到类型名; 版本后缀保留, 例如 `xdg_wm_base` -> `WmBase`, `zwp_tablet_tool_v2` -> `TabletToolV2`.
- 若剥离后在包内产生碰撞, 该包全部 interface 回退为完整 CamelCase 名; 规则必须由生成器测试覆盖.
- Go 包名由协议目录名去掉 `-` 与 `_` 后小写, 例如 `xdg-shell` -> `xdgshell`; 导入路径保留目录名.
- 枚举类型名 = `<Interface><Enum>`; 常量名 = `<Interface><Enum><Entry>`; 避免包内重名.
- 每个有事件的 interface 生成一个 `<Type>Handler` 接口; 创建对象时传入; 事件方法按 XML 顺序, 返回值为空.
- 请求方法带 `since` 检查; 返回 error; `new_id` 返回对应的生成类型; `object` 参数使用对应的生成类型指针, `allow-null` 允许 nil.
- 事件参数: 标量, 字符串, 数组, fd, enum 使用生成类型; `object` 与 `new_id` 参数在 v0.1.0 使用 `*wayland.Proxy`, 由调用方按元数据判断接口. 生成类型的子对象包装与类型化事件对象是已知限制, 不在 v0.1.0.
- 有事件的 interface, 构造时 handler 必须非 nil; nil 返回 `ErrInvalidArgument`. 无事件的 interface 不生成 handler 参数.
- 生成的每个协议文件带 `// Code generated by waylandgen; DO NOT EDIT.` 头; 手写代码不得写入 `protocols/`.

## 后果

- 正面: 命名短且可读; 包名消除协议前缀; handler 类型安全; 生成规则可被测试逐条覆盖.
- 负面: 剥前缀需要碰撞回退, 生成器复杂度上升; 事件 object / new_id 参数在 v0.1.0 是 `*Proxy`, 类型安全弱于请求侧; 用户需要查看元数据才能处理这类事件.
- 需要同步修改: `docs/contracts.md` 的生成 API 模板与 exemplar; 生成器测试; 示例只使用 v0.1.0 覆盖的参数形态.

## 不可逆性

- 以后改回: 改所有生成的导出名与 handler 接口, 所有调用方与示例; 发布后需要 major 版本.
- 分级: 高.
- 回滚方案: v0.1.0 前可整体重生成; 发布后提供旧命名别名包或新 major, 不静默改名.
