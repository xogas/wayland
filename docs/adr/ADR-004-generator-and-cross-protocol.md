# ADR-004: 生成器架构与跨协议引用

- **状态**: Accepted
- **日期**: 2026-11-15
- **决策人**: 库作者
- **触发**: 改变对外契约 (生成代码布局与依赖边)
- **不可逆性**: 中

## 背景

生成器要读取 68 个 XML, 校验 DTD 与语义, 生成根包与 `protocols/` 下的绑定, 并保证同一输入两次生成无 diff. 68 个 XML 中有 21 处跨协议 interface 引用, 其中 `xdg_toplevel` 在 stable 与 unstable xdg-shell 重名. 需要决定生成器内部布局, 元数据归属, 跨协议 import 规则与写入策略.

## 备选方案

生成器布局:

| 方案 | 优点 | 缺点 |
| :--- | :--- | :--- |
| A. `cmd/waylandgen` + `internal/gen` | 子包不可被外部导入 | 需要 ADR 解释 `internal/`; 与默认禁止 `internal/` 冲突 |
| B. `cmd/waylandgen` 子包 (`parse`, `model`, `render`) | 不使用 `internal/`; 路径简单 | 子包技术上可被外部导入, 但不承诺 API |
| C. 公开 `wayland/gen` | 可复用 | 扩大公开 API 与维护面 |
| D. `cmd/waylandgen` 单 main 包, 按文件拆 parse / model / render | 包少; 线性流水线; 无子包导入面 | main 包文件较多; 不能按包复用 |

元数据归属:

| 方案 | 优点 | 缺点 |
| :--- | :--- | :--- |
| A. 全部 interface 元数据生成到根包 | 动态 bind 可按名称解析; 生成包统一引用 | 根包元数据表较大 |
| B. 每个协议包自带元数据 + 注册表 | 包内自足 | 需要注册机制或全局状态; 动态 bind 难 |

## 决策

- 生成器布局选择 D: `cmd/waylandgen` 是单个 main 包; 按 `parse.go`, `model.go`, `render.go` 文件拆分阶段; 不建子包, 不建 `internal/`.
- 全部 interface 元数据生成到根包 `protocol_meta_gen.go`; 生成包通过 `wayland.InterfaceByName` / `wayland.MustInterface` 取得只读元数据; 动态 bind 按名称解析.
- 跨协议引用: 唯一 interface 按名称全局解析; 重名按 stable 优先; 仍有歧义则生成失败 E-13. 生成代码 import 目标协议包; import 边只由生成器写入.
- 生成入口: 模块根 `//go:generate go run ./cmd/waylandgen`; 默认输入 `wayland-protocols/`, 输出模块根; `-root` / `-out` 只用于测试或显式运行.
- 写入策略: 全部生成到临时目录, 成功后原子替换; 失败清理; 输出不含时间戳与本机路径; 文件顺序按协议路径与 interface 名稳定排序.
- 生成文件头固定 `// Code generated by waylandgen; DO NOT EDIT.`; `protocols/` 下不允许手写 `.go`.

## 后果

- 正面: 动态 bind 有统一元数据来源; 生成包不需要各自注册; 跨协议 import 由生成器控制; 失败不会留下半成品.
- 负面: 根包元数据表较大; `cmd/waylandgen` 是单个 main 包, 文件较多, 不能按包复用; 跨协议 stable 优先是项目规则, 与上游未来变化可能冲突, 需要升级时重新生成.
- 需要同步修改: `docs/design/modules.md` 的依赖白名单; `docs/contracts.md` 的 `InterfaceByName` / 生成命令; `scripts/check-dep.sh`.

## 不可逆性

- 以后改回: 改生成器布局, 元数据位置与跨协议 import 规则; 生成结果与 import 路径会变, 调用方可能需要重新生成.
- 分级: 中.
- 回滚方案: 重新生成即可回退输出; 生成器布局变更需要新 ADR 与一次全量重生成.
