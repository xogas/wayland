## Moved-code list

### Runtime

- `display.go` -> `dispatch.go`: `Display.Dispatch`, `(*Display).dispatchOne`, `(*conn).deliver`, `(*Display).handleDisplayEvent`.
- `display.go` -> `roundtrip.go`: `roundtripHandler`, `roundtripHandler.Done`, `Display.Roundtrip`, plus the new per-call `roundtripState` (`softTimeout`, atomic `canceled`, callback tombstone, read-deadline setter, and `unread` that calls the existing `conn.unreadFrame` immediately).
- `display.go` -> `close.go`: `Display.Close`.
- `conn.go` -> `connect.go`: `Connect`, `DialContext`, `DialFD`, `resolveSource`, `newDisplay`.
- `conn.go` -> `io.go`: `errSoftTimeout`, `sendRequest`, `write`, `ensure`, `oobSize`, `readMore`, `readFrame`, `unreadFrame`, `takeFD`.
- `conn.go` -> `close.go`: `conn.close`, `closeFDs`; `wire.go` -> `close.go`: `closeArgFDs`, `closeOOBFds`.
- `conn.go` stays: `conn` struct, `beginDispatch`, `isClosed`, the client/server/message constants, the `hooks *testHooks` pointer, and the dispatch guard fields.
- `object.go` and `wire.go` stay the object table and codec; only the hook call in `deleteID` and the close helpers changed location.

### Roundtrip state

`conn` no longer carries permanent `softTimeout` / `roundtripCanceled` fields. Roundtrip creates one `roundtripState`, stores it in `conn.roundtrip`, and clears it to nil in the defer. `readMore` reads `conn.roundtrip.softTimeout` for the soft-deadline translation. `dispatchOne` reads `conn.roundtrip.canceled`; when set it puts the consumed frame back with `roundtripState.unread` and returns `errSoftTimeout`. The cancel path still uses `context.AfterFunc`, `SetReadDeadline`, and `markTombstone` in the same order, so R02 semantics are unchanged: context error returned, connection usable, canceled callback not delivered, unrelated events preserved, tombstone retained until `delete_id`.

### Test hooks

- `testHooks` and `newTestHooks` moved from `conn.go` to `testhooks.go`.
- All hook access goes through methods on `conn`: `testInstallHooks`, `testSetRawName`, `testRawName`, `testNoteSkipped`, `testSkippedEventCount`, `testSetSkipUnknownServer`, `testSkipUnknownServer`, `testUnknownServerSkips`, `testSetOOBLen`, `testOOBLen`.
- `dispatch.go` calls `c.testSkipUnknownServer`, `c.testRawName`, and `c.testNoteSkipped`; it has no hook fields or hook branches.
- `io.go` calls `c.testOOBLen` from `oobSize`; `object.go` calls `c.testSkipUnknownServer` from `deleteID`.
- `testutil_test.go` keeps `installTestHooks` / `skippedEventCount` as thin wrappers over the methods; the S-05 raw-bind tests and the `wire_s03` MSG_CTRUNC test use the setters/getters.
- `conn.hooks` is a single pointer, nil on every production path. `TestRawSkipMarkerOffDoesNotWeakenUnknownObjects` still proves that default dispatch reports E-07 and increments no skip counter.

### Generator

Functions were moved mechanically; no generator declaration was added, removed, or rewritten. The model/build code and reference resolution went to `model.go`; naming and collision validation to `validate.go`; shared name conversion to `names.go`; rendering orchestration to `render.go`; type/handler/enum/request rendering to `render_types.go`; metadata literals to `render_meta.go`; bind rendering to `render_binds.go`; and Go type/expression/name helpers to `render_names.go`.

No standalone opcode helper existed in the original generator: opcodes are assigned in `buildMessage` and emitted from `m.Opcode` in `renderRequest`. No helper was invented; that keeps the renderer output byte-identical.

## Deviations, remaining structural debt, and blockers

- **Generator prose in frozen docs**: `docs/design/modules.md` describes the generator as `parse.go`, `model.go`, `render.go`. The requested S-07 split is finer-grained. The module boundary is unchanged (still one `cmd/waylandgen` main package importing only the standard library), but the prose is now less specific. `docs/design/modules.md` is frozen, so it was not edited; this evidence records the deviation for the repository owner.
- **No standalone opcode helper**: the review item mentioned opcode helpers, but the original generator had none. Opcode assignment remains in `buildMessage` and rendering reads `m.Opcode`; no new helper was invented, so generated bytes stay identical.
- **Examples duplication**: the five examples still repeat connection/registry boilerplate. That is outside S-07 (a structural refactor of the runtime and generator, not a new example package or shared example helper), and sharing it would require a new package decision.
- **Generated code size**: `protocol_gen.go`, `protocol_meta_gen.go`, and `protocols/**` remain large committed generated deliverables by design; this slice does not hand-edit or restructure them.
- **Live counter variance**: `unknown_child_skips` varies with the compositor's event timing (118-120 on both HEAD and the refactored tree). The acceptance run above matches the published S-05 count of 120, and no deterministic counter or protocol behavior changed.
- **Raw-bind fd limitation**: unchanged from S-05/S-06. Without a generated signature, descriptors carried by an unknown event cannot be identified and are not individually closed; tests avoid fd events on raw objects.
- **AC-X03 / AC-X04**: still MANUAL PENDING, unchanged. This slice did not run or claim those manual checks.
- **Blockers**: none. The slice is committed; generated and frozen paths have no diff.
