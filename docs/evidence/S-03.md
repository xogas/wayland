## 实现说明与偏差

### 动态 new_id 线格式

`wayland.xml` 的 `wl_registry.bind` 只声明 `name` 与 `id` 两个 arg. 真实线格式与公开的 `wl_registry_interface.bind` 处理函数一致, 为 `name, interface(string), version(uint), id(new_id)`. 修复前 sway 直接返回:

```text
wayland: protocol error: wl_display object 1 code 1: invalid arguments for wl_registry#2.bind
```

由于本切片不允许改生成器, 也不允许手改生成代码, 运行时在 `encodeRequest` / `decodeArgs` 对 `ArgNewID` 且 `ArgSpec.Interface == ""` 做动态展开:

- 编码时从对象表中取出调用方刚分配的目标 Proxy, 写入 `interface.Name`, `Proxy.version`, 再写 new_id.
- 解码时读回 interface 名与 version, 解析为 `*Proxy`; 未知 interface 或 version 越界返回 E-15 (`ErrInvalidArgument`).
- 68 个 XML 中只有 `wl_registry.bind` 有动态 new_id; `TestWireCoverage` 覆盖 598 requests / 443 events 时也覆盖了该路径.

这不是生成代码变更, 也不需要改 XML. 它把 libwayland 对 dynamic new_id 的 scanner 特例放在运行时实现.

### FD 所有权与部分写

- 发送 fd 由调用方持有, 库不关闭; `TestWireFD/two_and_one` 在 Send 与 Close 后仍能 `fstat` 原 fd.
- 接收 fd 归调用方; 跳过事件 (`ErrNoHandler`, destroyPending, tombstone) 的 fd 由库关闭. `skipped_event_fd_closed` 与 `destroy_pending_event_fd_closed` 用 pipe EOF 验证.
- 一条 fd 消息第一次 `WriteMsgUnix` 携带全部 fd; 部分写后的续写不再重复 ancillary. 若重复, 收端会收到重复 fd, 违反 fd 数量与顺序. `partial_write_ancillary` 用 1KB `SO_SNDBUF` 与 60KB 消息验证收端恰好收到 2 个 fd 且顺序与发送一致. 这是对契约 8.3 "部分写重试同一 ancillary" 的按不重复交付解释.
- `MSG_CTRUNC` 返回 E-06 并关闭连接; 测试用 `oobLen=16` 的内部测试钩子触发, 不耗尽进程 fd.

### 取消与 tombstone

- `Roundtrip` 用 `context.AfterFunc` 安装 `SetReadDeadline(time.Now())`, 并在 defer 中 `stop()` / 等待回调结束 / `SetReadDeadline(time.Time{})` 复位.
- `readMore` 只在 `softTimeout` 期间把 deadline 错误转换为内部 `errSoftTimeout`; 其他读错误仍是 E-04 并关闭连接.
- 取消的 callback 保留在对象表中作为 tombstone; 其事件被消费并关闭 fd, 不交付 sink; 收到 done 后标记 destroyPending, 收到 delete_id 后释放.
- 取消与读事件竞态时, 已读出的 frame 通过 `unreadFrame` 放回读缓冲, 下一次 Dispatch 再处理, 不消费其他对象的事件; `TestRoundtripCancelPreservesEvents` 覆盖.
- `TestRoundtripCancel` 验证: 超时返回 `context.DeadlineExceeded`; 连接未关闭; done 不交付; tombstone 在 delete_id 前存在, delete_id 后消失; 后续 Roundtrip 成功; 已取消 context 立即返回 `context.Canceled`.

### Close 与回调

- `callbackActive` 只在用户 sink 执行期间置位; Close 先关闭 socket, 再检查该标志.
- 回调内或回调并发期间 Close 返回 `ErrInvalidOperation` 且不等待 `dispatchMu`; 其他情况 Close 关闭 socket 后等待 `dispatchMu`, 因此阻塞的 Dispatch 先返回 `ErrClosed`.
- 协议 / IO 错误路径调用内部 `conn.close()`, 不等待 `dispatchMu`, 避免自锁.
- 并发 Close 由 `closeMu` 串行化, 重复 Close 返回 nil.

### delete_id 规则

- 只允许 destroyPending 对象与 serverOwned 对象 (例如 wl_callback) 的 delete_id.
- live 的非 serverOwned 对象, 重复 delete_id, 未知 ID, `wl_display` id 1 的 delete_id 均为 E-07 并关闭连接.
- 回收 ID 只在 `[1, 0xFEFFFFFF]` 内加入空闲表; 服务端范围 ID 删除后不进入客户端分配器.

### 其他实现选择

- `syscall.FcntlInt` 在 linux/amd64 的 `syscall` 包不存在; 使用等价的 `syscall.Fstat` 验证正 fd.
- 非 allow-null 的 string / object / new_id null 在解码时返回 E-10; array 的 0 长度在 wire 上无法区分 null 与空, 解码按空处理. 编码 / 发送对非 allow-null 的 `Array(nil)` 仍返回 E-10 (AC-W05 的 Given 是编码或发送).
- `wl_display.error` 的 `object_id` 按 uint 解码, 允许 0 或已消失对象, 仍返回 E-05; 已知对象填充 `Interface`. `TestProtocolErrorZeroObject` 覆盖 object id 0.
