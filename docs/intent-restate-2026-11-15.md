# 意图复述: wayland (2026-11-15)

复述对象: `docs/intent.md` (v1.0 Frozen).

## 我理解的目标

你要一个不依赖 CGO 与 libwayland 的 Go Wayland 客户端库. 它自己负责连接, 线协议编解码, 对象与事件分发, 并带一个开发期命令: 读取仓库里 vendored 的 68 个协议 XML, 生成并提交 Go 绑定. 这样你以后写 Linux 桌面小工具时, 克隆仓库后直接 `go build` 就能得到单文件二进制, 不必每个工具都重做静态链接和交叉编译.

## 我理解的使用场景

使用者是你自己: 在 sway 桌面上写截图, 启动器这类小工具, 大约每月新建一个. 每个工具都从干净 clone 开始, 产物在本机 sway 上运行, 不依赖目标机的 libwayland.so.

## 我理解的痛点

现在每做一个新工具, 都要重新处理 CGO 与 libwayland 带来的静态链接和交叉编译, 大约每月一次, 每次半天. 产物还依赖目标机上的 libwayland.so, 没法单文件分发.

## 交付后你会看到什么

- 模块根包放 wayland.xml 的绑定; `protocols/` 下按 stable/staging/unstable/experimental 和协议目录放其余绑定.
- 仓库根有一条生成入口. 它读取 68 个 XML, 生成或更新绑定; 连跑两次, 第二次 `git diff` 为空; `go build ./...` 与 `go vet ./...` 通过.
- 68 个 XML 都能通过 wayland.dtd 校验. 解析结果与 XML 源在 interface 名称/版本, request/event 名称/opcode, 参数类型, 接口与 enum 引用, enum 名称/取值上逐项一致; 生成代码里的元数据与解析结果也逐项一致.
- 所有 interface/enum 引用可解析, request/event 的 opcode 从 0 连续, `since` 不超过所属 interface 版本, enum 取值不重复且能放进 32 位整数.
- 每条 request/event 至少有一条编解码用例, 覆盖 int/uint/fixed/string/array/fd/new_id/object, 空 string/array, 对齐补零; 截断消息返回错误, 不 panic; `go test -race ./...` 通过.
- v0.1.0 交付时, 5 个示例都能独立连上本机 sway 并以 0 退出: registry 列出 global; shm-surface 显示 200x200 纯色; xdg-shell 显示 400x300 窗口, 标题 `wayland-go demo`; input 打印键盘 keycode 与指针坐标; output 打印显示器 name/分辨率/scale. 另有一个 registry-bind 检查, 把 sway 广告的每个 global 按广告版本绑定一次, 不产生 protocol error.

## 一个具体输入与期望输出

输入: 在仓库根执行生成入口.

期望输出: 68 个 XML 全部读取成功; 根包与 `protocols/` 下的绑定被更新; 再执行一次, `git diff --exit-code` 返回 0; 接着 `go build ./...` 与 `go vet ./...` 返回 0.

输入: 运行 registry 示例.

期望输出: 标准输出列出本机 sway 的 global, 至少包含 `wl_compositor`, `wl_shm`, `xdg_wm_base`; 进程退出码 0.

## 我理解的非目标

- 不做服务端/compositor, 不生成服务端绑定.
- 不在库或示例里引入 CGO, 不链接 libwayland, 也不调用 wayland-scanner 或其他 C 实现.
- 不碰 X11/XWayland.
- 不做 EGL/OpenGL/Vulkan/DRM/GBM 或渲染 API; 示例只用 `wl_shm`.
- 不做窗口管理, 控件, 布局, 主题这类高层 UI.
- 不在运行时解析 XML, 不做插件式协议; 绑定只在开发期生成并提交.
- 对 sway 没广告的协议, 不声称真实连接可用; 交付说明会按协议标注验证到了哪一层.

## 我理解的约束

- Go 1.27.4 起, 只用标准库, 第三方依赖 0.
- 只支持 linux/amd64. Wayland 的 32 位值按主机字节序编码, 该机器是小端, 所以直接按小端编码, 不做字节序转换; 其他平台默认不支持, 不加构建标签.
- 协议来自仓库内 wayland 1.26.0 + wayland-protocols 1.50 的 68 个 XML; 生成代码提交进仓库.
- 实现只依据协议 XML, wayland.dtd 和公开协议文档; 不以 C 代码为依据; 线协议以文档为准, 以真实合成器互通为验收.
- 并发上, 可以从不止一个 goroutine 同时发请求; 事件分发和核心状态由库内部串行处理, 回调不会并发执行; 调用方不需要额外加锁.
- experimental 协议跟随上游; 上游更新 XML 就重新生成; 不承诺 API 跨版本不变.
- 个人项目, 没有截止日期; 完成标准就是上面 `交付后你会看到什么`.
